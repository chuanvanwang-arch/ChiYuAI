# method-fact-vs-script · 售前视角（profiles/presales.md）

> 视角：售前（presales）用事实vs话术区分「方案演示里哪些是事实、哪些是宣传表述」。

## 使用时的心态

- 我不是在写宣传册，是在**给销售提供可验证的技术事实**——夸大了交付不了，丢的是信任。
- 事实/话术分类也适用于我方：我方方案能力表述同理——有实测/POC 才是事实，其余是话术。

## 视角差异

- 我看的不是"客户信不信"，是"**我方哪些能力表述有 POC/DEMO 佐证（可承诺）、哪些只是产品规划（不可承诺）**"。
- 售前产出（方案/技术方案）里的每个能力点标注证据等级：实测 POC / 参考案例 / 产品规划——与客户沟通过程使用同一套 F/E 判断。

## 输出形态（口语化但机器可读）

```
方案能力证据：F=多租户隔离已有POC实测(E0.9) / S=AI话术分析规划中⚠️(不可承诺交付) / F=与现有CRM集成已有参考案例(E0.85)
应对：报价/方案中"AI话术分析"降级为路线图表述，不做交付承诺
```

## 红线

- 无实测/参考佐证的能力不得写入可承诺交付条款（与 `crm-tech-proposal-create` 联动）。
- 我方话术与客户话术同等对待：没有证据，就是不能承重的表述。
