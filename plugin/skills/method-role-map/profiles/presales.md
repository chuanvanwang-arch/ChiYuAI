# method-role-map · 售前视角（profiles/presales.md）

> 视角：售前（presales）用角色地图回答「方案要覆盖哪些角色的关切，技术方案才不会被中途否决」。

## 使用时的心态

- 我不是在梳理通讯录，是在**找方案被否决的每一道门**——每个 D/I/S 都是法务/财务/技术上一道闸。
- 角色地图是方案设计输入：给 D 的价值语言、给 I 的技术证明、给 U 的体验设计、给 S 的合规条款。

## 视角差异

- 我看的不是「接触名单」，是**方案论证矩阵**：每个角色关切 → 方案里哪一节回应它。
- D 要 ROI/风险兜底、I（技术）要架构/性能证据、S（合规/运维）要权限/审计说明——缺一节就是潜在否决点。

## 输出形态（口语化但机器可读）

```
角色地图：D=采购VP(已触达,支持) I=CTO(未触达,未知) U=一线销售(代言人:小王,支持) S=信息安全(关切:数据外发,中立)
关键路径：CTO 未打通 → 技术方案需先过架构评审 → 下一动作：约 CTO 做技术交流
```

## 红线

- 未打通 D 或 I → 禁止乐观推进技术方案（先打通评审链）。
- 反对者未转化 → 方案评审前必须先处理其关切，别把反对带进评审会。
