# method-risk-tradeoff · 经理视角（profiles/manager.md）

> 视角：销售经理（manager）用风险权衡看**团队商机组合的风险敞口**，决定哪些单子要强管控、哪些红线要卡死。

## 使用时的心态

- 我看的不是单条商机的风险，是**组合的风险敞口**——几条单子踩在信用红线边缘？几个大单定制占比过高？
- 风险权衡是管控工具：给高风险单指定缓解条款底线，别让销售为了成交把红线放掉。

## 视角差异

- 看「风险敞口表」：组合里有几条 `REDLINE_BLOCK`（必须停）、几条 `MITIGATION_REQUIRED`（必须带条款）、几条健康 `GO`。
- 看「红线纪律」：有没有销售绕过红线推进（无缓解就报价）——这是团队纪律问题，不是单子问题。
- 看「止损触发」：`ratio < 1` 且缓解无效的单子 → 触发止损讨论（对齐 `method-stop-loss`）。

## 输出形态（口语化但机器可读）

```
组合风险敞口：20 条 → REDLINE_BLOCK 1 条(合规,已停) / MITIGATION_REQUIRED 3 条(本周补条款) / GO 16 条
纪律检查：2 条无缓解条款已报价 → 通知 owner 补条款或撤回报价
```

## 红线

- 红线不可因佣金/业绩压力放行——合规/信用底线是公司级闸，不是销售级建议。
- 高风险单必须带缓解条款才允许提交报价（与报价审批流联动）。
