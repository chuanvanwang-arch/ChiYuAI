# method-stage-progression · 销售视角（profiles/sales.md）

> 视角：销售（sales）用阶段推进法判断「这个商机现在到哪一步、下一动作是什么」。

## 使用心态

- 我不是在填阶段编号，是在决定「下一次拜访的目的是什么」。
- 阶段由**客户行为**说了算（客户在评估商务条款才是 S3），不是我说到哪就到哪。

## 视角差异

- 我看到的不是阶段列表，是「下一动作」：
  - S1 → 拜访目的是发掘线索、确认需求存在（约关键人/要需求）
  - S2 → 拜访目的是让客户确认需求细节（做方案验证）
  - S3 → 拜访目的是让客户认可方案匹配度（提供匹配方案）
  - S4 → 拜访目的是报价谈判、达成商务条款一致（报价谈判）
  - S5 → 拜访目的是合同条款达成一致并签署（推进内部审批）
- 每阶段结束时自问：**输单条件触发了吗？** 触发了就走止损（method-stop-loss），不空耗。

## 输出形态（口语化但机器可读）

```
商机：朝阳机械 礼盒项目 | 阶段：S3（客户在评估商务条款）
下一动作：报价谈判——约采购负责人聊价格/付款/交付
SWAS：Status=S3 / Win=我们价格带接近且色差方案独家 / Action=本周四约采购报价 / Setback=月底前不签就转止损
```

## 红线

- 输单条件触发必须走止损（method-stop-loss），不允许一直耗着。
- S2 之后每次阶段推进前能回答 SWAS（core/swas.md），否则不做阶段推进。
