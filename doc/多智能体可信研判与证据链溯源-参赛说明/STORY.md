# STORY.md — 多智能体可信研判与证据链溯源系统 · ChiYu AI（参赛作品说明）

## 1. 叙事目标
- **场合**：AI 应用类赛事评审（项目简介 + 作品说明 PPT + 演示视频）
- **受众**：评委（技术 + 产业 + 投资混合背景），对"又一个多智能体框架"与"又一个更高精度模型"高度警惕
- **一句话主张**：研判系统已经把"出结论"做得足够快，但**结论凭什么成立**仍是黑箱；ChiYu 让每一条研判结论都带着它的证据链、推理链与分歧记录，**可追溯、可复核、可干预**。
- **必须在评审心中建立的三个认知**：
  1. 我们**不宣称**模型本体精度更高、行业语料更多——这两项不是我们的壁垒，我们**接入与配置**
  2. 我们**做**的是判断的可信度结构：三维置信度度量 × 博弈对抗消解 × 三级证据溯源 × 推理树全程可审
  3. **不覆盖分歧、不自动处置**：少数意见留档，结论进人工复核闸，这是可信研判的底线而非妥协

## 3. 逐页叙事要点
- **01 封面**（hero）：品名 + 主张副标 + 参赛信息位；右侧抽象 SVG（结论节点向证据、来源三级展开）。
- **02 目录**（supporting）：四章（技术方案 / 应用场景 / 落地效果 / 团队介绍），每章一句引导。
- **03 立论**（hero）：巨型锚点数字 `100%`（结论可下钻到原始来源的比例·设计目标）；点破行业判断——研判已经很快，缺的是"凭什么信它"。
- **04 痛点**（supporting）：四卡并列，每卡一个痛点 + 一句后果，全部落在"结论生成之后"。
- **05 方案总览**（supporting）：研判全链路条（采集→抽取→入图→多角色研判→冲突识别→对抗消解→因果校验→推理树→人工复核归档）+ 三大能力块 + 三场景胶囊。
- **06 架构**（hero）：三层智能体 SVG 大图（L0 研判集群 / L1 仲裁消解 / L2 审计追溯）+ 右侧认知支柱（K-M-D + 三维置信度）。
- **07 三维可信度量**（supporting）：信源可信度 × 证据强度 × 逻辑一致性三列 + 九尺子逐项打分 + 决策第 0 闸。
- **08 冲突消解**（supporting）：冲突识别分类 → 博弈对抗（正方/反方/仲裁）→ 五策略消解表 → 保留少数意见不覆盖。
- **09 证据溯源与因果校验**（supporting）：结论→证据→来源三级下钻 + 证据图谱关系 + 因果校验三关（时序优先/反事实/混杂排查）。
- **10 推理透明与全程可审**（supporting）：推理树四态节点 + 中间结论留痕 + 哈希链防篡改 + 可复现与人工干预重算。
- **11 落地与验证**（hero）：巨型数字 60,290（源程序行数）+ V1.0 软件著作权 + PoC 三阶段；明确"研判域暂无第三方客户案例，指标待实测"。
- **12 对标与价值**（supporting）：表格 6 行（含 2 行主动认弱），读表说明不针对特定厂商。
- **13 团队与知产**（supporting）：团队（占位待补）+ 软著 / 专利 / 商标状态 + 合规边界声明。
- **14 结束页**（hero）：收束金句 + 落款 + 诚实性标注。

## 4. 诚实性红线（全篇遵守）
- **不虚构**第三方研判客户案例、不虚构准确率 / 误报率下降 / 冲突消解成功率等量化收益。
- 未落地能力标 `[规划]`；待确认信息标 `[待补充]`；设计目标与实测指标严格区分。
- 量化指标仅在"已确证"时使用（源程序 60,290 行、V1.0 软件著作权、发明专利交底 5 件分批递交）。
- 演示视频与场景推演均标注"能力运行逻辑推演，非生产环境实录"。
