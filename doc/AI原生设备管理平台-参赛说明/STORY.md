# STORY.md — AI 原生设备管理平台 · ChiYu AI（参赛作品说明）

## 1. 叙事目标
- **场合**：AI 应用类赛事评审（项目简介 + 作品说明 PPT + 演示视频）
- **受众**：评委（技术 + 产业 + 投资混合背景），对"又一个 IoT 看板"高度警惕
- **一句话主张**：工业互联网平台已把"连接与可视化"做到成熟，但**判断与闭环**仍是空白；ChiYu 把老师傅的经验、判断与处置记忆，变成设备群自己的认知与闭环。
- **必须在评审心中建立的三个认知**：
  1. 我们**不做**连接层的重复建设（诚实认弱：协议、组态、生态成熟度不如存量平台）
  2. 我们**做**的是判断与闭环：设备记忆体 + 可解释决策 + 业务闭环 + 复盘回写
  3. **判断可解释、人工复核**是工业红线，我们明确不自动执行生产操作

## 3. 逐页叙事要点
- **01 封面**（hero）：品名 + 主张副标 + 参赛信息位。
- **02 目录**（supporting）：四章（技术方案 / 应用场景 / 落地效果 / 团队介绍），每章一句引导。
- **03 立论**（hero）：巨型数字对比或一句话"S 条告警 → 1 条根因"；点破行业判断——数据之后，谁来判断。
- **04 痛点**（supporting）：四卡并列，每卡一个痛点 + 一句后果。
- **05 方案总览**（supporting）：EAM 全链路条（台账→点检→监测→告警→诊断→工单→维修→备件→复盘）+ 三大能力块。
- **06 架构**（hero）：三层智能体 SVG 大图（L0 边缘 / L1 集群 / L2 业务）+ 右侧认知支柱。
- **07 K-M-D 管道**（supporting）：K 知识层 → M 方法层 → D 决策层（九尺子 + 9 列决策记录）+ 决策第 0 闸。
- **08 设备记忆体**（supporting）：五类记忆 + 写库即构建 + 语义检索先例。
- **09 应用场景**（supporting）：锅炉集群连锁告警 / 重复故障根治 / 新人接手陌生设备。
- **10 对标**（supporting）：表格 6 行（含 2 行主动认弱），读表说明不针对特定厂商。
- **11 落地与验证**（hero）：巨型数字 60,290（源程序行数）+ V1.0 软著 + PoC 三阶段；明确"设备域暂无客户案例，指标待实测"。
- **12 商业价值**（supporting）：市场空白 + 互补定位 + 配置画像复制。
- **13 团队与知产**（supporting）：团队（占位待补）+ 软著 / 专利 / 商标状态。
- **14 结束页**（hero）：收束金句 + 落款。

## 4. 诚实性红线（全篇遵守）
- **不虚构**设备行业客户案例、不虚构告警收敛率 / 停机下降等量化收益。
- 未落地能力标 `[规划]`；待确认信息标 `[待补充]`。
- 量化指标仅在"已确证"时使用（60,290 行源码、V1.0 软著、5 件专利交底已成稿）。
