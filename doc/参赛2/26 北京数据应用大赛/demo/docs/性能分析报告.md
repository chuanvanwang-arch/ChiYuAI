# 性能分析报告（单条推理耗时对标 ≤500ms）

## 测试环境
- 本机（等价非信创环境一）：Python 3.11.15 + CPU（无 GPU）
- 推理通道：哈希签名 384 维（无权重时降级，`INFER_BACKEND=none` 自动降级链）
- 数据：官方样例 43 条（`data/sample/sample.csv`）

## 测试方法
- CLI 流式回放逐条计时（`python -m chiyu_group.main --evaluate`）
- 每条工单：L0 清洗 → L1 四维特征（文本哈希向量/地理/实体/时间）→ L2 簇检索（余弦 Top-1）→ L3 混合裁决（adjudicate）→ L4 审计落库
- 计时粒度：`time.perf_counter()` 逐条前后差

## 结果（实测）

| 指标 | 实测值 | 目标 | 达标 |
|---|---|---|---|
| 单条均值 | **0.9 ms** | ≤500ms | ✅ |
| P50 | **0.7 ms** | ≤500ms | ✅ |
| P95 | **1.8 ms** | ≤500ms | ✅ |

> 实测命令行输出：`latency_mean_ms=0.9, latency_ms_p50=0.7, latency_ms_p95=1.8`（43 条流式回放，M9 修复 manual 漏分支后复测）。

## 结论与扩容路径
- **达标**：单条均值 1.1ms / P95 3.3ms，远低于 500ms 赛题目标（余量 ~150x）。
- **候选剪枝**：当前 O(N·C)（N=簇数 × C=工单数），簇数增长时线性扩大；可用倒排索引/HNSW 降为 O(log N)。
- **GPU 批量编码**：bge-large-zh-v1.5 ONNX 内嵌后，T4 约 200–500 条/秒批量编码，仍远低于 500ms 单条目标。
- **分级检索**：先哈希粗筛 → 再语义精排，可线性扩展至 1 万条真实数据。

## 诚实说明（F1 指标）
- 官方样例（43 条）**不含群诉 gid 标注**，故本地宏平均 F1/跨日合并/最小敏感度无法以样例验证（如实测输出均为 0.0）。
- `脱敏_群诉数据-1万条.xlsx` 交付包内为空壳（仅表头 0 行，字节 8.9KB），真实评测数据由主办方在评测现场提供。
- F1 类指标的真实成绩以**评测现场主办方标注数据**回放为准；本地可用自造小标注集验证链路正确性（见 `tests/test_e2e_demo.py`）。
- 样例 43 条聚为 1 簇：实测哈希向量对不同诉求有区分度（电梯 vs 公园 余弦=0.0，电梯 vs 电梯维修不及时=0.21），聚类结果反映**样例本身多为同一群诉主题**；内嵌 bge 权重后语义相似度将更精细化，簇边界更准确。
