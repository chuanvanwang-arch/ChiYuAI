## 1. 方案简述（500 字以内）

本方案面向 12345 市民热线动态工单流，提出以**诉求记忆体**为核心的群体性诉求智能发现方法，将本单位已申请发明专利的**双轨记忆系统**与 **K-M-D 三层决策管道**迁移至工单聚类场景。

技术亮点有四。一是**四维相似度融合**：文本语义（bge-large-zh-v1.5 本地推理，1024 维）、地址空间（实测无经纬度与区划编码，走地名词典 + 层级粗匹配 + 区划硬约束的 ②③ 级降级通道）、实体关联（责任主体与事项本体的多跳关系图）、时间分布（指数衰减 + 复发周期识别）四路独立打分，经 RRF（K=60）融合排序，克服"同因异构表述"漏聚与"同表述异因"误聚两类经典误判。二是**双轨记忆驱动跨窗口合并**：日志轨仅追加原始工单，笔记轨幂等重写簇画像；簇到期经"蒸馏—归档"休眠而非删除，新工单命中归档簇即复活并标记为**延续性群体诉求**。三是**确定性优先的混合裁决**：8 项确定性规则加 1 项软评分，红线硬判定优先于置信度，结果可复现、可审计。四是**流式增量聚类**：新工单只与候选簇比对，复杂度由 O(N²) 降至 O(N·C)。方案**全栈闭网部署**，模型本地推理，数据不出政务网。

### （二）赛题理解（3000 字以内）

#### 1. 问题本质：这不是"文本聚类"，而是"记忆体识别"

赛题要求"基于工单文本语义、地址空间、实体关联、时间分布等多维信息，对动态工单流中的相似工单完成精准聚类，支持跨时间窗口合并延续性群体诉求，提升识别准确率与推理效率"。

我们对该表述的拆解是：**赛题的真实目标不是把相似的文本聚到一起，而是识别出一个持续存在的"诉求主体"**——同一个小区反复出现的夜间施工噪声、同一个开发商旗下多个楼盘的延期交付、同一条街道连续三周的占道经营。这类"主体"具有长期身份，会间歇性复发，会在不同市民的口语化表述下呈现出截然不同的文本形态。

因此，本方案将问题重构为：**为每一个潜在诉求主体建立一个可寻址、可累积、可休眠、可复活的"记忆体"，新工单到达时判定其归属于哪个记忆体，或是否应当创建一个新的记忆体。** 这一重构直接决定了技术选型——传统的"全量文本向量 + 离线聚类"范式无法承载"身份"这一概念，因为它每次都在重新聚类，不保留跨批次的状态。

**必须厘清的口径：群体性诉求 ≠ 重复诉求。** 群诉定义为"同一区域、同一事件引发的批量投诉"，统计口径挂在**聚类（事项）**而非投诉人；**同一人反复投诉（一人多诉）属重复诉求，不计入群诉**。本方案对同一诉求人的重复工单做**独立标记与降权**——不删除（保留证据价值），但簇规模统计与预警触发按"独立诉求人数 / 独立地址数"计数，杜绝单人反复提交触发虚假预警。

#### 2. 六个关键技术难点

**（1）语义相似 ≠ 诉求相同。** 工单文本存在两类相反方向的干扰：一是**同因异构表述**（同小区电梯故障，市民分别描述为"电梯老是卡住""上下不方便"），纯文本相似度易漏聚；二是**同表述异因**（"噪声扰民"或来自广场舞、装修、空调外机、地铁施工，成因与责任主体完全不同），纯文本相似度易误聚。解决思路是**语义只作为四路信号之一**，由地址与实体维度承担"成因一致性"的鉴别责任。

**（2）地址维度的口语化与多粒度。** 市民填写的地址常为口语化描述（如"XX 小区南门那栋"），同一地点多种叫法，且合理聚合粒度随事项类型变化（一栋楼的电梯故障 vs 一个区的供暖不达标）。对样例数据实测确认：**数据无经纬度与行政区划编码**，问题点位含"不详/缺失约 22%、打星脱敏约 32%、常规文本约 46%"。解决思路是按**三级降级通道**落地：以地名词典 + 层级粗匹配为主通道（承办单位前两字=区名，可直接作为免费区域锚），口语化 / 不详地址走归一化文本相似 + 区划硬约束；若后续取得区划编码或经纬度，再启用①级多层级网格增强，动态升级无需改上层逻辑。

**（3）实体关联的隐式性。** 责任主体（物业、开发商、施工单位、商户）往往不在工单中显式出现，需从文本与历史工单中抽取并关联。同一主体可能在工单中以简称、别称、全称出现。解决思路是构建**实体—工单二部图**，以主体共现与文本指代消解建立边，实体相似度按**一跳强关联、二跳衰减**计算，并允许跨工单传递关联（同物业的 A、B 与同开发商的 B、C 之间形成二跳弱关联）。

**（4）时间维度的双重语义。** 时间在本赛题中有两层含义：一是**邻近性**（相隔 2 小时的两条工单比相隔 2 个月的更像同一事件）；二是**周期性**（夜间施工噪声每晚复发、供暖问题每年冬季复发）。单纯的指数衰减会漏掉周期复发，单纯的周期检测会误聚历史同类事件。解决思路是**双通道时间建模**：主通道用指数衰减刻画邻近性，辅助通道对归档簇做周期剖面（小时 / 星期 / 月份分布）匹配，命中周期即允许跨窗口合并。

**（5）动态流下的增量计算约束。** 工单持续到达，若每次都对全量历史重跑聚类，成本随规模平方增长，无法满足推理效率要求。解决思路是**增量聚类 + 候选集剪枝**：新工单先经四维融合检索出 Top-K 候选簇（而非全量簇），仅对候选簇做归属判定；无命中才创建新簇。

**（6）准确率与效率的取舍必须由治理规则兜底。** 纯数据驱动聚类无法杜绝"把无关工单聚到一起"的硬错误。解决思路是在判定层引入**红线优先**机制：涉及不同行政区划、互斥事项类别、已确认责任主体冲突的候选，无论相似度多高均强制不予合并；高价值判定（如拟上报的群体性诉求）转人工确认。

#### 3. 解题主要思路

**（1）总体思路：把"客户记忆"泛化为"诉求记忆体"。**
本单位专利中的"客户记忆"，本质是一种**以实体为锚点、跨事件累积、带生命周期治理的长期记忆结构**。热线场景中"客户"替换为"诉求主体"（地址实体 / 责任主体 / 事项主题的组合）。该泛化不需改造内核，只需重定义锚点解析与写入触发规则，是本方案相较从零建模的核心效率优势。

**（2）四层技术框架：**

- **K 知识层（用什么判）**：事项分类本体、地址标准词典与别名词典、聚合粒度配置、四路相似度权重、红线规则集、阈值配置——**全部配置化**，不在代码中硬编码任何业务字面量，口径变化无需重新发版。
- **M 记忆层（记得什么）**：双轨存储。日志轨仅追加原始工单事实（含四维特征与证据来源），笔记轨幂等重写簇画像（中心向量、空间范围、主体清单、时间剖面、代表工单摘要、未核实项标注）。簇休眠后标记归档但**永不删除**，保证跨窗口可召回。
- **D 决策层（判什么）**：对新工单执行"归属判定"——8 项确定性评分（语义、空间、实体、时间、簇规模、簇活跃度、证据完备度、冲突检测）+ 至多 1 项软评分（语义成因一致性），外置权重反算置信度；**红线判定先于置信度判定**，命中红线强制转人工在环；判定结果、依据、所引先例、策略版本统一落库，形成可审计追溯链。
- **闭环回流（第三条腿）**：预警与处置结果回流触发三段改写——复盘生成新知识（新事项类别、新地址别名）、后见之明改写记忆（误聚拆分、漏聚合并）、证实性偏差校验（判定评分与人工结论比对，偏差超阈值触发权重自适应）。

**（3）四维相似度融合的具体设计：**

| 维度 | 信号来源 | 计算方法 | 权重配置 |
|---|---|---|---|
| 文本语义 | 工单标题 + 内容 | bge-large-zh-v1.5 稠密向量余弦（异常降级为哈希签名余弦）+ 关键词稀疏命中 | 配置化 |
| 地址空间 | 问题点位（实测无区划编码与经纬度 → ②③级降级）+ 承办单位区名锚 | 地名词典层级粗匹配 + 归一化文本相似 + 区划硬约束（跨区置零）；①级网格编码为可插拔增强 | 配置化 |
| 实体关联 | 责任主体 / 事项实体 / 关联工单 | 实体集合 Jaccard + 图谱多跳衰减关联度 | 配置化 |
| 时间分布 | 工单时间戳 + 簇时间剖面 | 邻近性指数衰减 + 周期剖面匹配加成 | 配置化 |

融合采用两阶段：各维度独立产出候选排序，再以 RRF（score = Σ 1/(rank + 60)）融合排序，避免量纲不可比问题；同时设**单维度否决**与**单维度加速**两类配置化规则。

**（4）跨时间窗口合并的实现路径：**
1. 簇在连续 N 天无新工单后进入**静默期**；
2. 静默期结束经**蒸馏**生成蒸馏版簇画像（保留中心语义、主体清单、时间剖面，压缩原始工单明细），标记 `distilled`；
3. 再经一个周期标记 `archived`，簇转入**休眠态**，仍可被检索召回，但不参与常规候选集；
4. 新工单若在**扩展检索**（包含归档簇）中命中某归档簇，且空间与实体维度强匹配，则触发**簇复活**：恢复为活跃态，并在时间维度上标记为"**延续性群体诉求**"，输出复发间隔、历史处置结论与未解决标注。
这一机制的工程价值在于：**跨窗口合并不需要保留全量明细，也不需要重跑历史聚类**，只需比对蒸馏后的簇画像，推理成本与历史数据量近似解耦。

**（5）推理效率的工程保障：**
- 候选集剪枝：先用空间网格 + 事项类别做硬过滤，再做四维融合检索，候选集规模可控；
- 增量更新：新工单只更新命中簇的画像（幂等重写），不触碰其他簇；
- 分级检索：活跃簇与归档簇分离存储与检索，常规判定只扫活跃簇；
- 降级容错：向量服务不可用时自动降级为确定性哈希签名，链路不中断。

#### 4. 预期达成的赛题指标

本方案预期在三方向形成可量化提升：**识别准确率**（降低同表述异因误聚）、**发现率与及时性**（提升同因异构表述的召回并提前预警时点）、**推理效率**（单条判定复杂度与历史总量解耦）。数值以赛题评测实测为准，评测方案见"数据方案"。

### （三）核心优势（1000 字以内）

**1. 创新性**

- **范式创新：从"聚类"到"记忆体识别"。** 现有工单聚类方案多为"批次向量化 + 离线聚类"或"规则分桶"，本质是无状态的。本方案引入**带身份、带生命周期、带证据链的诉求记忆体**，使系统具备跨批次状态，这是"跨时间窗口合并延续性诉求"能够成立的前提。
- **机制创新：归档即休眠，复用即复活。** 借鉴专利中的"遗忘表现为归档而非删除"设计，簇的消亡不是数据消失而是转入休眠，命中即复活并标注延续性。该机制将"历史数据保留"与"在线推理效率"这对矛盾统一起来——历史不丢，但不参与常规计算。
- **融合创新：四维独立打分 + RRF 排序融合 + 确定性优先裁决。** 规避了加权求和在量纲不可比时的失真，同时以红线优先机制确保软评分永远不会越过硬约束，这在政务强合规场景中尤为关键。
- **架构创新：闭环回流第三腿。** 处置结果反向改写知识层与记忆层，使系统具备自我进化能力，而非一次性模型。

**2. 有效性**

- **技术有效性有现成验证。** 双轨记忆、RRF 混合召回、混合决策三项核心机制均已在生产系统（多租户 SaaS）中长期运行，并已申请发明专利，不是实验室原型。
- **误聚可控。** 红线规则与单维度否决从机制上杜绝了"跨行政区合并""互斥事项合并"等硬错误；人工在环通道保障高价值判定的责任可追溯。
- **降级不中断。** 推理服务不可用或算力受限时自动降级为确定性哈希签名，系统可用性不依赖单一组件，零 GPU 环境亦可完整运行。
- **效果可度量。** 判定结果全量落库（含评分明细、所引证据、策略版本），支持事后逐条复盘与指标归因。

**3. 可推广性**

- **领域无关的内核。** 记忆体内核不绑定热线业务语义，锚点、触发规则、权重、阈值全部配置化，迁移到网格事件、信访、市场监管投诉、交通拥堵上报等"群众诉求流式汇聚"场景时，只需重新配置 K 知识层，无需改动代码。
- **全栈闭网可部署，满足政务数据不出网要求。** 核心栈为 Node.js + PostgreSQL（pgvector），普算侧信创（ARM）与 x86 双栈均可；向量编码与语义软评分**全部本地推理，零公网 API 依赖**，模型权重离线导入；无 GPU 时可纯 CPU 降级运行。
- **标准化对外服务。** 能力已封装为 MCP 协议服务，可被第三方智能体直接编排调用，便于与现有热线业务系统集成，避免推倒重建。
- **增量式落地路径。** 可先以"辅助提示"模式与现有系统并行运行，验证准确率后再切换为"自动识别"模式，降低上线风险。

## 二、详细方案

### （一）数据方案（3000 字以内）

#### 1. 赛题配套竞赛数据的使用说明

**（1）数据接入与字段映射**

赛题配套竞赛数据为本方案的**唯一训练与评测数据源**。依据出题单位公开的数据结构表与配套样例数据，工单记录包含以下字段：工单编号、工单标题、工单内容、推送时间（YYYY-MM-DD HH:MM:SS）、承办单位、问题分类（三级分类标签，形如"城乡建设>施工管理>施工扰民"）、问题点位（可为地址、道路、小区或地理坐标等）；训练数据另含群诉标注（群诉事件 ID / GID 与是否群诉标记），测试数据不含标注。本方案按如下方式使用：

| 数据字段（官方结构表） | 用途 | 处理动作 |
|---|---|---|
| 工单编号（VARCHAR(20)） | 日志轨唯一标识 / 评测输出键 | 作为记忆条目外部键；评测输出 `order_id+gid` 以本字段为主键 |
| 工单标题 + 工单内容（脱敏后） | 文本语义信号 | 拼接后截断至模型上限（480 字符，对应 512 token）→ 稠密向量；保留原文用于稀疏关键词通道 |
| 推送时间（DATETIME） | 时间维度信号 | 归一化为时间戳；派生小时 / 星期 / 月份周期特征，用于簇时间剖面与跨日合并 |
| 承办单位（区分中心 / 镇 / 市直部门） | 区域锚 + 实体信号 | 作为**免费行政锚点**：承办单位前两字多为区名（朝阳 / 海淀 / 大兴…），可校验地址归一化并作为区域硬约束补充；同时为责任主体备选 |
| 问题分类（三级标签） | 知识层本体 | 构建事项分类本体；三级标签（如 城乡建设>施工管理>施工扰民）作为候选集剪枝与红线的硬过滤条件 |
| 问题点位（地址 / 道路 / 小区；脱敏含星号，实测不详 22% / 打星 32% / 常规 46%） | 空间维度信号 | **实测定级**：无经纬度与区划编码 → 直接走 ②③ 级降级（地名词典 + 层级粗匹配，承办单位前两字=区名作区域锚；口语化 / 不详地址用归一化文本相似 + 区划硬约束）；①级（区划编码 / 网格编码）保留为可插拔增强 |
| 事件ID / GID（训练标注） | 评测标注 | 用于监督阈值训练与簇纯度评估；测试集不含此列 |
| 是否群诉（训练标注） | 评测标注 | 用于群诉二分类评测与最小成诉敏感度评估 |
| 测试集标识（训练集内） | 评测切分 | 区分训练 / 测试子集并保持时间序 |

**（2）实测数据形态（基于出题单位配套样例数据 EDA）**

依据配套样例数据（50 条真实脱敏工单，跨 2026-01-09 至 2026-06-12，约 5 个月）与数据结构表，实测关键形态如下：

| 实测项 | 结论 |
|---|---|
| 时间跨度 | 样例跨度约 5 个月（2026-01~06），支持日 / 周 / 月群诉评测 |
| 问题分类 | 三级标签（一级 12 类：城乡建设 / 市场管理 / 住房 / 社会培训机构 / 卫生健康 / 劳动和社会保障 / 交通管理 / 公共服务等；全三级标签约 37 种）——**可直接用于红线硬过滤与本体构建** |
| 承办单位 | 形态为"区分中心 / 乡镇 / 市直部门"（海淀区分中心、朝阳区分中心、市交管局、顺义区仁和镇等）——**前两字即区名，可作为免费区域锚与地址归一化校验** |
| 问题点位形态 | 无区划编码、无经纬度；**不详 / 缺失约 22%，打星脱敏约 32%，常规文本约 46%**——地址维度**确定走②③级降级**（地名词典 + 层级粗匹配 / 归一化文本相似 + 区划硬约束），有区划编码的①级为可选增强 |
| 文本形态 | 标题平均约 14 字符、内容平均约 219 字符（口语化 + 模板化，含"市民反映 / 工单来源"等固定前缀）——清洗重点为模板前缀与个人信息 |
1. **文本清洗**：去除个人信息（手机号、身份证号、姓名、银行卡号等）——复用专利中的**凭证硬拒闸门**，凭证类内容一律剔除或脱敏，不作为相似度计算输入；去除无意义模板化尾部（如"请尽快处理"）。
2. **地址归一化**：建立三级归一——①**标准地址解析**（省市区街道社区 + 路名门牌 + 小区名 + 楼栋单元）；②**别名词典**（同小区多叫法、简称全称、历史地名），词典由训练数据自动挖掘（共现地址 + 高语义相似）并经人工抽检确认；③**地理网格编码**（多层级网格，支持按事项类型选择聚合粒度）。
3. **实体抽取与消解**：从文本中抽取责任主体（物业、开发商、施工单位、商户、政府部门）与事项实体（设施、设备、场所），建立别名词典与共指消解规则。
4. **向量化**：文本经清洗后由**内网本地推理服务**生成 1024 维向量（政务数据不出网，不调用公网 API）；**采用"写时向量化"策略**——数据入库即完成向量化，不存在事后补建窗口，从而天然支持流式场景。
5. **噪声过滤**：空内容、纯测试、重复提交、明显误填的记录在进入记忆轨之前被拦截，并留痕可统计。

**（3）数据集划分与评测设计（对齐出题单位评分口径）**

- **时间序划分**：严格按时间切分训练/验证/测试集（而非随机切分），以真实还原"动态工单流"场景——用 T 之前的数据构建记忆体，用 T 之后的数据评测归属判定与跨窗口合并能力。这一点至关重要：随机切分会泄露未来信息，导致评测结果虚高。
- **在线评测方式**：以**流式回放**方式评测——按时间顺序逐条喂入工单，模拟真实到达（需满足单条处理 ≤500ms 的硬指标），记录每一步的判定结果、候选集规模、响应耗时，从而同时度量准确率、召回率与推理效率。
- **对比基线**：设置三组基线——①纯文本向量聚类；②文本 + 地址简单加权；③本方案（四维融合 + 记忆体 + 红线裁决），以量化各模块的贡献。
- **指标定义**（与出题单位评分表对齐，三类客观分）：①**群诉识别 F1（20 分）**——以工单-群诉归属结果计算**宏平均 F1**（每个群诉事件独立计算再取平均，防止大群诉掩盖小群诉）；②**跨日合并准确率（10 分）**——评估跨时间窗口同一群诉是否被正确合并（日 / 周 / 月群诉）；③**最小成诉敏感度（10 分）**——对 **3~5 件小规模群诉**的召回能力，评估模型对小规模、早期群诉事件的发现能力。群诉覆盖判定以"同一区域 + 同一事件"为口径。推理性能硬指标：**单条平均耗时 ≤500ms**。
- **主观分对齐**（60 分）：算法创新性（特征设计 / 相似度度量 / 聚类策略 / 动态阈值）20 分、成果实用性（可落地 / 推理效率与资源占用 / 结果可解释性）25 分、成果完整性（代码规范 / 文档完整度 / 答辩演示）15 分——本方案在可解释性（红线留痕、评分明细落库）与推理效率（流式增量 O(N·C)）上有直接的得分支撑。
- **群诉成诉阈值（官方口径）**：出题单位明确**群诉事件标准 ≥5 件**，真实评测集已按该阈值判定；本方案将阈值设为**可配置多级（黄 / 红）**并默认"≥5 件成诉"为基准，同时保留"3~5 件小群诉早期识别"的敏感度调优目标。
- **取向声明**：本方案默认**召回 / 及时性优先、容忍一定误报**（误报由红线与人工在环兜底），该权衡将在答辩中显式说明；最终口径以出题单位发布的打榜规则为准。
- **人工校验集**：从测试集中抽样构造人工标注集（建议 300–500 条判定样本），用于红线规则与权重阈值的校准，以及人工在环环节的效果评估。

### （二）技术方案（4000 字以内）

#### 1. 算法原理

##### 1.1 四维相似度计算

**（1）文本语义相似度 $s_{text}$**

对工单文本 $T$ 与簇画像中心文本 $T_c$，分别计算：
- **稠密通道**：$s_{dense} = \cos(E(T), E(T_c))$，其中 $E(\cdot)$ 为**内网本地部署**的 BAAI/bge-large-zh-v1.5 编码器，输出 1024 维向量（政务数据不出网，不使用任何公网 API）。文本超长时按 480 字符截断（对应 512 token 上限）。
- **稀疏通道**：$s_{sparse} = |Q_T \cap Q_{T_c}| / |Q_T \cup Q_{T_c}|$，基于关键词集合（去除停用词后的名词与动宾短语）。
- **降级通道**：当本地推理服务不可用时，自动切换为**确定性哈希签名向量**余弦——将文本映射为固定维度（384 维）的哈希签名，结果可复现，保证链路不中断。该通道使系统在**零 GPU 环境**下仍可完整运行。

**（2）地址空间相似度 $s_{space}$**

$$s_{space} = \alpha \cdot \mathbb{1}[admin_{equal}] \cdot \left( \gamma^{level(g_T, g_c)} \right) + (1-\alpha) \cdot \exp(-\lambda \cdot d(p_T, p_c))$$

其中 $admin_{equal}$ 为行政区划一致性指示（不同区直接置零，属红线约束），$level(g_T, g_c)$ 为两地址在多层级网格中的最近公共祖先层级，$\gamma$ 为层级衰减系数，$d(p_T, p_c)$ 为归一化后的地理距离，$\lambda$ 为距离衰减系数。聚合粒度（楼栋 / 小区 / 社区 / 街道 / 区）按事项类型由知识层配置。

**地址维度三级降级（可插拔，实测定级 ②③）**：对配套样例数据实测（50 条真实脱敏工单）确认：**无区划编码、无经纬度**，问题点位含"不详/缺失约 22%、打星脱敏约 32%、常规文本约 46%"，因此本赛题地址维度**确定走②③级**：②仅街道 / 小区文本 → 地名词典 + 归一化 + 层级粗匹配（承办单位前两字=区名，可作免费区域锚）；③仅口语化 / 不详地址 → 归一化后文本相似度，以行政区划作硬约束（跨区直接置零）。①级（区划编码 / 网格编码）保留为可插拔增强接口。三级共用接口，切换不改上层逻辑。

**（3）实体关联相似度 $s_{entity}$**

$$s_{entity} = \beta_1 \cdot Jaccard(E_T, E_c) + \beta_2 \cdot \sum_{e \in E_T} \max_{e' \in E_c} \delta^{hop(e, e')}$$

其中 $E_T, E_c$ 为工单与簇的实体集合，$hop$ 为关系图最短跳数，$\delta$ 为跳数衰减（一跳强、二跳弱、三跳以上不计）。关系图由"实体—工单"二部图构建，边权随共现次数累积。

**（4）时间分布相似度 $s_{time}$**

$$s_{time} = \max\left( \exp(-\mu \cdot \Delta t), \; \eta \cdot Periodic(h_T, w_T, m_T \mid \mathcal{P}_c) \right)$$

主通道刻画邻近性（$\Delta t$ 为距簇最近活动的时间间隔）；辅助通道计算工单时间特征（小时 / 星期 / 月份）与簇历史剖面 $\mathcal{P}_c$ 的匹配度，识别周期性复发。$\eta$ 为周期通道权重，**仅在簇处于静默 / 归档态时提升**——只对休眠簇开放跨窗口合并，避免活跃簇误聚。

##### 1.2 融合与候选生成

各维度独立对候选簇排序，采用 **RRF（Reciprocal Rank Fusion）** 融合：

$$score(c) = \sum_{v \in \{text, space, entity, time\}} w_v \cdot \frac{1}{rank_v(c) + K}, \quad K = 60$$

RRF 不要求各维度量纲可比，且对单一维度极端值不敏感。另配两类规则：
- **单维度否决**：任一维度得分低于否决阈值（如空间跨区、实体互斥），直接剔除候选；
- **单维度加速**：语义与实体双高但时间较远时，允许候选进入"跨窗口复核"通道。

##### 1.3 归属判定（D 层混合裁决）

对 Top-K 候选簇执行九尺子混合评分：
- **8 项确定性评分**：语义一致性、空间一致性、实体一致性、时间邻近性、簇规模合理性、簇活跃度、证据完备度、冲突检测结果。确定性规则每次重算结果一致，可复现。
- **1 项生成式软评分**：由**内网本地部署**的大模型判断"两条工单的成因是否为同一件事"，用于处理规则难以覆盖的语义歧义。该评分为可选项，可关闭（关闭后系统退化为纯确定性模式，无需语言模型算力、延迟更短）。
- **置信度反算**：按外置权重聚合反算综合置信度 $conf$。
- **红线优先**：**红线判定先于置信度判定**——若命中红线（跨行政区划、互斥事项类别、已确认责任主体冲突、涉及敏感类别），无论置信度高低，一律不予自动合并，强制转入人工在环。
- **决策落库**：判定结果（归属簇 / 新建簇 / 转人工）、评分明细、所引证据、生效策略版本快照统一落库，分配判定标识，形成可审计追溯链。

##### 1.4 簇生命周期与跨窗口合并

```
新工单 → 四维检索（活跃簇）→ 候选集 → 归属判定
                                        ├─ 命中 → 更新簇画像（笔记轨幂等重写）
                                        ├─ 未命中 → 扩展检索（含归档簇）
                                        │            ├─ 命中归档簇 → 【簇复活】标记"延续性群体诉求"
                                        │            └─ 未命中 → 创建新簇
                                        └─ 命中红线 → 人工在环
簇状态机：活跃 →(N 天无新工单)→ 静默 →(蒸馏)→ 已蒸馏 →(归档)→ 休眠（可召回，不参与常规候选）
                                                              ↑__________ 复活 __________|
```

**蒸馏**生成压缩版簇画像（保留中心语义、空间范围、主体清单、时间剖面，压缩原始工单明细）；**归档**仅置标记，**永不物理删除**。因此跨窗口合并的推理成本与历史工单总量近似解耦——比对的是蒸馏后的簇画像，而非全部历史工单。

##### 1.5 群体性诉求判定与预警分级

簇本身不等同于群体性诉求，须经**规模与时效**双重判定后才升级为预警：
- **计数口径**：按**独立诉求人数 / 独立地址数**计数而非工单件数；同一诉求人的重复工单降权合并，防止"一人多诉"虚增规模——群诉是"多点共振"，不是"一人反复"。
- **区域—事项双约束**：须同时满足"同一区域 + 同一事件"才计入；仅事项同而区域分散属普遍性问题，仅区域同而事项异属区域综合热度，均不计入。
- **群诉成诉阈值（官方口径）**：出题单位明确**群诉事件标准 ≥5 件成诉**（同一区域 + 同一事件 + 同一主体引发批量投诉；一人多诉不计入），评测集已按该阈值标注——本方案以 **≥5 件**为成诉基准判定，同时保留**最小成诉敏感度调优目标（3~5 件小群诉早期识别）**，与评测指标（最小成诉敏感度 10 分）对齐。
- **多级预警阈值**（存于知识层，非硬编码）：**黄色——≥5 件成诉基准线（单日批量或 3 日累计）；红色——累计 ≥10 件或涉及敏感类别**，红色预警强制转人工确认；阈值可按簇规模分布动态校准。
- **时效衰减与推送**：规模按时间衰减加权，避免陈旧工单长期顶高簇规模；达阈值触发预警，输出簇画像（中心语义、空间范围、主体清单、时间剖面、代表工单、独立诉求人数），红色预警强制转人工确认。

##### 1.6 闭环回流

处置结果回流触发三段改写：
1. **复盘生成新知识**：误聚产生互斥规则与地址别名修正，漏聚产生同义表述与实体别名；
2. **后见之明改写记忆**：人工确认的误聚簇拆分、漏聚合并，并更新簇画像；
3. **证实性偏差校验**：比对判定评分与事后人工结论，偏差超阈值触发权重自适应建议（需人工确认生效）。

## 三、应用成效（2000 字以内）

### （一）提升程度分析

本方案针对赛题三项核心诉求——**精准聚类**、**跨时间窗口合并延续性群体诉求**、**提升识别准确率与推理效率**——分别形成可量化的提升路径。

**1. 聚类精准度：从"文本相似"到"成因一致"**

传统纯文本向量聚类的两类系统性误差在本方案中被机制性地抑制：
- **同因异构表述导致的漏聚**：由地址维度与实体维度补足。同一小区、同一责任主体的工单，即使文本表述差异极大，仍可通过空间强匹配与实体强关联召回。预期在"同小区同类设施故障"这类典型场景上显著改善召回。
- **同表述异因导致的误聚**：由红线规则与单维度否决抑制。跨行政区划、互斥事项类别、责任主体冲突的候选被硬性剔除；实体维度的 Jaccard 相似度对"噪声扰民"这类泛化表述具有天然的区分能力。

由于判定结果全量落库（含四维评分明细、所引证据、策略版本），上述提升可逐条归因，而非黑箱结论。具体提升幅度将以赛题评测集在"纯文本基线 / 文本+地址基线 / 本方案"三组对照下实测得出。

**2. 跨时间窗口合并：从"历史不可见"到"休眠可复活"**

这是本方案最具差异化的提升点。现有批次聚类方案中，历史工单要么全量参与计算（成本高），要么被时间窗口截断（历史不可见）——二者不可兼得。本方案通过"蒸馏—归档—复活"机制实现兼得：
- 历史簇以蒸馏画像形式保留（体积小、语义完整、含时间剖面）；
- 归档簇不参与常规候选集，不影响在线推理效率；
- 新工单在扩展检索中命中归档簇即触发复活，并明确标记为**延续性群体诉求**，同时输出复发间隔、历史处置结论、是否曾实质解决。

对热线业务而言，这一能力的直接价值是：**"这个诉求我们三个月前处理过，但没解决，又来了"**——从依赖人工记忆变为系统自动关联。

**3. 推理效率：从 O(N²) 到 O(N·C)**

- **候选集剪枝**：空间网格 + 事项类别硬过滤先行，候选集规模与历史总量解耦；
- **增量更新**：新工单只更新命中簇画像，不触碰其他簇；
- **分级检索**：活跃簇与归档簇分离，常规判定只扫活跃簇；
- **批量与缓存**：向量编码可批量提交，热点簇画像常驻内存。

综合效果是单条工单判定的时间复杂度由与历史总量相关的 O(N²) 降至与候选簇数相关的 O(N·C)，且 C 远小于 N。在百万级历史工单规模下，这一差异决定了方案能否在线运行。

**4. 可审计性与可信度**

判定结果、评分明细、所引证据、生效策略版本、人工干预记录统一落库，支持逐条复盘与责任追溯。对政务场景而言，"为什么说这两条工单是同一件事"必须可以回答，这是纯向量相似度方案无法提供的。

**5. 自我进化能力**

闭环回流机制使方案不是一次性模型：误聚/漏聚样本产生新的互斥规则与别名修正，偏差校验触发权重自适应建议。随着运行时间增长，准确率呈持续改善趋势，而非随数据分布漂移而衰减。

### （二）经济社会效益

**1. 经济效益**

- **直接降低处置成本**：群体性诉求由"多件重复办理"转为"一件批量处置"，减少重复派单、重复现场核查与重复回复。按热线工单量中群体性诉求占比估算，合并处置可节约相当比例的重复处置人力。
- **降低管理成本**：诉求记忆体沉淀了事项的责任主体、历史处置结论与未解决标注，减少跨部门协调与信息重复采集成本。
- **节约信息化投入**：方案为领域无关的通用内核，可通过配置复用于网格事件、信访、市场监管投诉、交通上报等多类诉求汇聚场景，避免各部门重复建设；技术栈全部基于开源软件，无商业许可费用，信创与 x86 双栈可部署，避免硬件绑定。
- **可增量落地**：支持"辅助提示"与"自动识别"两种运行模式，可在不替换现有系统的前提下并行验证，降低试错与切换成本。

**2. 社会效益**

- **从被动响应转向主动治理**：延续性诉求的自动识别使"反复投诉但未解决"的问题显性化，推动资源从事后处置前移至源头治理。对市民而言，最直观的感受是"不用反复打同一个电话"。
- **提升公共资源配置的精准度**：群体性诉求的空间分布、时间剖面与责任主体清单，为城市治理的资源投放提供数据依据——哪里在反复出问题、什么时段高发、谁是责任主体，均可量化。
- **风险早发现早处置**：群体性诉求的数量增长与空间扩散趋势可作为社会风险的早期信号。本方案对"同一诉求在多小区扩散"具备天然识别能力（实体关联维度），有助于在矛盾激化前介入。
- **保障数据安全与合规**：全流程默认开启个人信息识别与脱敏，凭证类内容在写入记忆前即被拦截；判定可审计、责任可追溯，满足政务系统对算法可解释性与数据安全的要求。
- **推动 AI 技术在政务领域的规范化应用**：本方案以"确定性优先、红线不可逾越、人工在环兜底"为设计原则，为生成式 AI 在强合规政务场景中的落地提供了一个可复制的治理范式——不让模型的软判断越过硬约束，这在当前大模型应用普遍缺乏治理机制的背景下具有示范意义。
