## §4 ★ 架构纪律：内核可复用，域模型必须分离

这是本评估最重要的一条技术结论，也是 APS 项目一轮实测教训的**推广**。

### 4.1 事实

APS 平台层（资产 C）的粒子模型是**排产域**的，且**已冻结**：

- `src/aps/platform/schema.py:107` 注释原文：「粒子类型（#1 Step 1：C0-C4 收敛，**9 个真粒子 ≤ 15**）」
- `PARTICLE_TYPES`（`schema.py:124`）实为 **9 个排产域粒子**（`SCHEDULING_CASE` / `SLAB` / `UNIT` / `ORDER` / `RESOURCE` …）
- `schema.py:113` 注释原文：粒子类型定义「= `data.particle` 的 type 值，**绝不为每粒子开 CRUD**」

而**设备诊断域需要的是另一组粒子**：`EQUIPMENT`（设备）/ `COMPONENT`（部件）/ `FAULT_MODE`（故障模式）/ `CAUSE`（原因）/ `MEASURE`（措施）/ `INSPECTION`（点检记录）/ `WORK_ORDER`（维修工单）/ `VIBRATION_SAMPLE`（振动样本）——与排产域**无一重合**。

### 4.2 判据（写成纪律）

> **平台内核可复用，域模型必须分离。**
> 复用：粒子库 DDL 与读写原语（`store.py`）、审计链（`audit.py`）、记忆分层、上下文 L1–L4、决策双通道、事件总线、Action 注册表机制、投影保真度。
> 分离：**域 schema 独立成模块**（如 `schema_equipment.py`），**绝不往 APS 的 9 粒子表里追加设备域粒子**。

### 4.3 为什么不能用"共用一张 `particle` 表"的省事做法

1. **`PARTICLE_TYPES` 是封闭枚举 + 单一事实源**，追加即破坏"9 个真粒子"不变量（该不变量有测试断言把守，见 APS 侧 `tests/test_platform.py` 对 `catalog_summary()` 的数量校验）；
2. **CRUD 爆炸**：`data-particle-*` 是覆盖全粒子类型的泛化 CRUD，追加粒子类型会连带扩大 Action 面，正是 Action 表面基数纪律要禁止的形态；
3. **域语义污染**：排产域的 `SCHEDULING_CASE` / `SLAB` 与设备域的 `EQUIPMENT` / `WORK_ORDER` 共用一张表，会让"案例作用域身份"（`CASE_SCOPED_IDENTITY`）等纪律失去边界。

★ **同一原则在上一轮的形态**：frePPLe 借鉴项 P1（违例物化）被判定**不得新增粒子类型**，须走独立的 `violation` 表。本榜的设备域是同一原则的**跨域推广**：**新增域 = 新增域 schema，而非新增粒子**。

## §5 三个真实缺口

### 5.1 缺口一：振动信号分析（唯一净新增技术，但是教科书级）

**已有资产为零**：APS 项目（排产）与 CRM 项目（销售）均无任何振动信号处理代码 —— 无 FFT、无包络谱、无峭度/裕度指标。

**但 4 类故障的判据是成熟方法**（业界通识，非研究性难题）：

| 故障类型 | 典型判据（教科书级） |
| :-- | :-- |
| 轴承磨损 | 包络谱中出现 **BPFO / BPFI / BSF / FTF** 特征频率及其谐波（需轴承几何参数） |
| 转子不平衡 | 频谱 **1× 转频** 幅值突出，轴向振动增大 |
| 齿轮异常 | 频谱在**啮合频率**及边带（±轴频）处抬升 |
| 润滑故障 | 高频段能量抬升、**包络谱**与**峭度**异常 |

⇒ 技术路线明确、可用 `numpy`/`scipy` 实现。**依赖面已实测**（2026-09-16）：

| 依赖 | 项目主用 venv（Py3.13.14） | 系统 hermes venv（Py3.11.15） |
| :-- | :-- | :-- |
| `numpy` | ✅ 2.5.1 | ✅ 2.4.6 |
| `scipy` | ❌ **缺失** | ✅ **1.17.1**（`scipy.signal` 的 `welch`/`hilbert`/`envelope`/`butter`/`filtfilt`/`find_peaks`/`stft` 均在） |
| `pandas` / `ortools` / `openpyxl` / `yaml` | ✅ 3.0.5 / 9.15.6755 / 3.1.5 / 6.0.3 | ✅ |

⇒ **scipy 不是阻塞项**（系统侧已有完整实现），但 **`pyproject.toml:9-14` 的依赖清单里没有 scipy** —— 若本榜真要落码，须显式补依赖声明，且**推荐在主 venv 加装而非切换解释器**（切换会牵动 ortools 9.15.6755 的回归面）。

★ **但比依赖更关键的是**：**必须有测试语料才能自证** —— 否则会落入"探针骗人"的陷阱（无标注样本时，无法证明判据有效）。

### 5.2 缺口二：数据可得性（★ 决定性）

原文两处措辞指向"数据由发榜方给定"：
- `:5`「本榜赛期验证诊断智能体核心能力：**在给定振动数据与运维知识上**…」
- `:10`「**接入**振动时序（含转速、温度）、点检记录与维修工单」

但**未明确数据集规模、是否随题下发、是否含标注**。这是**唯一的 go / no-go 判据**：
- 若给定**带标注**数据 → 可算出真实的分类准确率与误报率 → 本榜是**最可落地的一类**；
- 若仅给定**未标注**原始数据 → 只能做"判据合理性"展示，准确率不可声称；
- 若**不给定** → 与 A 榜同困境，全部参数标 ASSUMED，答辩时无法回应"准确率多少"。
