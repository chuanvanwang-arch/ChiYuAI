## 三、A 件·具体实施方式章节（草稿）

> 以下为可直接提交代理机构的实施方式正文（已用代码实名替换设计术语；锚点均经核实）。

### 3.1 系统构成

本发明实施的销售决策处理系统包括：业务事件触发器、上下文装配模块（L1–L4 分层）、评分模块 `rubricScorer`、自治引擎 `autonomyEngine`、红线校验模块 `adviceCard`/场景顾问、决策落库模块 `decisionRepo`、置信度反算模块 `confidence`、配置中心 `configStore`。各模块经事件总线 `events/bus` 协同，所有写操作经决策第 0 闸校验。

### 3.2 具体实施步骤

**S1 触发与上下文装配**。销售业务事件（如超权限报价）触发决策场景 `scenario_id`；系统从 `decision_scenario` 表加载该场景的必填维度 `required_dims`、聚焦尺子 `focus_rulers` 与默认处置档（`decisionRepo.js:32-62`）。同时装配 L1 知识底座、L2 历史决策、L3 执行协同、L4 治理决策四层上下文。

**S2 九尺子混合裁决（核心）**。评分模块 `rubricScorer` 对触发上下文执行固定顺序的九项评分（`rubricScorer.js:17-27`）：
- 清晰性 `clarity`（依赖 intent/assumptions，允许大模型精评 `llm:true`）；
- 准确性 `accuracy`、精确性 `precision`、相关性 `relevance`、深度 `depth`、广度 `breadth`、逻辑性 `logic`、重要性 `importance`（依赖 concept_refs）、公平性 `fairness` —— 八项均由代码规则确定性判定，尺度 0–4（0=缺失、4=充分）；
- 技术效果：同一决策重跑得分一致，使趋势与复合效应 Q(Skill,T) 有意义（`rubricScorer.js:4` 注释）。

**S3 证据双路合并**。自治引擎 `buildConditions` 生成条件模板：优先采用调用方显式传入的 `trigger_context.conditions`，否则自动加载 `CRM_METHODOLOGY_EVIDENCE` 证据粒子的采集结果（`autonomyEngine.js:50-70`）。每条条件记录 `evidence_source` 与 `evidence_ref`，回答"为何判该维达标"。

**S4 红线优先校验（核心安全特征）**。在执行自治放行前，先对上下文执行红线校验：
- 若命中业务红线（如 `redlines` 非空），输出 B 档处置"必须走审批流"（`adviceCard.js:35,65`）；
- 若处置标记为 `EXCEPTION`，则**无论置信度高低**，强制 HITL + 上级 role 背书 + 审计高亮（`autonomyEngine.js:244-245,316`）。
- 该排序保证：高置信度但触碰红线的建议**不会**被自动放行，根治"LLM 过度自信绕过治理"。

**S5 置信度计算与放行判定**。引擎以权重 `similarity:0.4, coverage:0.3, method:0.1, evidence_coverage:0.1, allMet:0.1` 合成置信度，阈值默认 0.7（`autonomyEngine.js:26-29`）；阈值/权重由 `config_store['autonomy-conf']` 外置读取，缺省回退默认（`autonomyEngine.js:34-42`）。置信度 ≥ 阈值且有先例 → 自主放行（A 档）；否则升级人工（C 档）。

**S6 置信度反算校准**。决策事后经 `computeConfidence` 反算：业务结果 `won/paid→0.9`、`lost/partial→0.3`、`stalled→0.5` 优先于人工 `CONFIRMED→0.85`、`OVERRIDDEN→0.2`，无信号回退引擎置信度或中性 0.6（`confidence.js:4-13`）。该反馈闭环校准后续放行策略。

**S7 决策落库与审计（核心）**。决策经 `createDecision` 写入 `decision` 表，至少包含：`decision_id`（mint）、`scenario_id`、`effective_policy_version`（决策时刻冻结的生效政策版本快照）、`disposition`、`confidence`/`confidence_source`、`concept_refs`（概念引用集合）、`conditions_evaluated`、`tenant_id`、以及八要素 `intent/assumptions/inference/viewpoints/implications/risk_register/stop_loss/concept_refs`（`decisionRepo.js:240-248`）。`concept_refs` 落库前回查 `methodology_dimension` 补全 canonical 权重/必填/标签（`decisionRepo.js:217-230`），消除手写维键盲区。决策因果边（DECIDED_ON / DERIVED_FROM_EXCEPTION 等）同步写入 `decision_relation` 与 AGE 镜像（`decisionRepo.js:424-444`）。

- 决策可复现：八项确定性评分使同决策重跑一致，趋势分析可用；
