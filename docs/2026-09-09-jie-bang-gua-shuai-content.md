## 3. 研究计划（主要研发内容、关键技术、创新点、技术路线）

### 3.1 主要研发内容

#### 内容一：科技管理高质量数据集构建与「写库即构建」治理
面向指南、项目、专家、成果、创新主体五类核心对象，构建覆盖科技项目全周期的高质量数据集。突破传统「先建库、后治理、再标注」的串行模式，采用**写入即物化**机制：数据在写入事务内同步完成向量化（embedding）、全文索引（tsvector）与本体（Ontology）同步三件事，并通过内容哈希判变实现幂等，避免重复计算与脏向量。

- 数据规模：≥10 万条结构化记录，≥6 类实体、≥20 类关系
- 质量保障：本体自动维护 + 向量去重与版本管理 + 覆盖率监控 + 补偿回填（backfill）

#### 内容二：面向国产大模型的科技管理场景适配层
构建模型无关的适配层，实现国产主流大模型的**可插拔接入 + 确定性优先编排 + 分级降级**：
- **确定性优先**：将评审规则、合规校验、形式审查等可判定环节下沉为确定性算法（本平台已验证的「九尺子」结构中 8 把为确定性尺子、仅 1 把由大模型裁决），大幅降低对模型输出的依赖与抖动。
- **上下文分层注入（L1–L4）**：知识底座 / 历史决策 / 执行协同 / 治理决策四层分级注入，各层独立超时（200 ms 级）与 fail-open 降级，任一层超时不拖垮整体响应。
- **向量双 provider 降级**：模型向量服务不可用时自动降级为哈希签名向量，保证检索链路可用性 100%。

#### 内容三：四阶段全流程智能化应用
1. **指南编制**：历史指南与政策知识检索、指南条目智能生成、与上位规划和已有指南的冲突/重复检测、合规校验。
2. **征集申报**：申报书形式审查自动化、创新主体画像匹配、申报材料缺项预警、智能问答（7×24）。
3. **组织实施**：项目里程碑跟踪、风险预警、专家智能匹配与回避检测、评审意见一致性与偏离检测。
4. **评估改进**：闭环回流机制——处置结果回写、根因归因、规则与阈值自动调优（每日复盘），形成「执行—回流—进化」闭环。

#### 内容四：全过程可信管控与审计
- **多智能体写操作多级安全闸门（八闸）**：决策来源闸（无决策不写）、数据范围闸、角色权限闸、功能权益闸、字段级权限闸、高危写强制闸、人工确认（HITL）闸、行为前置条件闸；对外通道同走闸并叠加两阶段确认令牌。
- **全链路可追溯**：每一次智能体写操作与裁决均生成唯一 decision_id，落库记录约 33 个字段（含概念引用、生效策略版本），支持正向追踪与反向溯源。

### 3.3 创新点

**创新点一：从「检索增强」到「写入即构建」的数据—知识转化范式。**
现有 RAG 方案多在查询侧增强，知识物化滞后于数据写入，导致向量与本体长期不一致。本项目将向量化、全文索引、本体同步前移到写入事务内，以内容哈希判变保证幂等，使知识库与业务库在同一事务边界内保持一致，从机制上消除「脏向量」与「本体漂移」。

**创新点二：确定性优先的大模型编排，将模型不确定性收敛到最小可控域。**
不把全流程交给大模型，而是以「九尺子」结构将可判定环节全部下沉为确定性算法，仅保留单一环节由模型裁决；配合上下文 L1–L4 分层与独立超时降级，使系统在模型不可用、响应超时、结果超阈值时仍可安全降级而非失控。

**创新点三：单源双视图——以派生代替冗余存储。**
指南与项目数据天然同时具有时间属性与关系属性。传统做法分别建时间线库与图谱库，双写双维护。本项目以单一数据底座为唯一事实源，时间线与图谱均为查询侧派生视图，实现「一次治理、双模复用」，消除一致性维护成本。

**创新点四：智能体写操作的多级闸门与全链路决策审计。**
针对智能体自主写库的可控性难题，构建八级串行闸门（含决策来源、范围、角色、权益、字段、高危强制、人工确认、行为前置），并对外通道叠加两阶段确认令牌；每次写操作与裁决生成唯一 decision_id 并完整落库，实现「任何一次自动写入都可解释、可追溯、可回滚」。

**创新点五：闭环回流的自我进化机制。**
将处置结果、根因归因、规则调优串成闭环，使规则与阈值随运行数据自动迭代，而非依赖人工周期性维护，解决「规则库上线即老化」问题。

### 3.4 技术路线

```
[数据层] 科技管理多源数据（指南/项目/专家/成果/主体）
    │  写入即构建（KT1）：向量化 + 全文索引 + 本体同步（哈希判变幂等）
    ▼
[知识层] 统一数据底座（唯一事实源）
    │  单源双视图（KT2）：时间线视图 ⇄ 关系图谱视图
    │  双轨记忆（KT4）：事件日志 + 常驻笔记（判定/提升/笔记化/蒸馏）
    ▼
[装配层] 上下文分层注入（KT6 L1–L4）+ 供给通道 S1–S7
    │  向量双 provider 降级；各层独立 200ms 超时 + fail-open
    ▼
[决策层] K-M-D 三层管道（KT3）：九尺子裁决（8 确定性 + 1 LLM）
    │  自治分级（置信度阈值 0.7 以上自动，以下转人工）
    ▼
[管控层] 写操作八闸（KT5）+ decision_id 全链路审计 + 受控渲染（KT7）
    ▼
[应用层] 指南编制 / 征集申报 / 组织实施 / 评估改进 四阶段应用
    │  多租户懒克隆隔离（KT9）
    ▼
[进化层] 事件总线 SSE（KT8）+ 闭环三段回流：结果回写 → 根因归因 → 规则调优
```

## 6. 验收方式（以是否解决实际问题为检验标准）

1. **现场验收**：在发榜单位指定真实业务场景现场运行，按 §5.1 指标逐项实测。
2. **第三方测评**：委托第三方机构对每项指标抽检 ≥100 条样本（满足榜单要求）。
3. **用户意见为主**：最终用户（管理人员 + 创新主体）满意度 ≥90%，并作为验收主要考量。
4. **刚性指标约束**：以立项时建立的客观、刚性评价指标为验收标准，未达标不予通过。
