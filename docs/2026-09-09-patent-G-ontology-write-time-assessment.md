## 〇、术语澄清

- **「写库即本体」** = 平台「写时构建（write-time building）」惯例：粒子落库同时自动完成本体同步（受控边+词汇登记）、向量化、检索索引建立——已落地。
- **「实时向量」** = 写入那一刻同步物化向量（而非批处理/事后建索引）——已落地（三钩子），但**当前向量是确定性哈希签名**，语义向量接口已预留未接真模型。
- **「实时回流」** = 事件落库/装配通过事件总线广播 + SSE 单连接实时刷新前端（monitor/portal）——已落地。
- 三者合起来是「**写时即时构建（图谱+向量）+ 事件驱动实时回流**」的完整管道。

## 四、可主张的发明点（结构级）

1. **三钩子写时物化 + 幂等判变**：`contentHash` 比对→内容未变不重算（省 LLM 额度、防索引漂移），变则双写 embedding+fts。
2. **双通道检索底座**：向量 + tsvector 全文索引**同步维护**（非批处理、非单选一），写后立即可用。
3. **向量 provider 显式降级协议**：哈希签名向量 + 真模型双 provider 标识；模型失效自动降级哈希并留痕，下游丢弃向量分量防污染（解决"把哈希当语义向量=注入常数噪声"这一真实技术问题）。
4. **写时本体同步**：引用字段自动建受控边（六映射）、域名证据建弱边（JSONB 元素级防子串误判）、词汇登记、审计事件——写入即成图。
5. **事件总线 + SSE 实时回流**：写事件广播（粒子/trace 域）→ 单连接 SSE 实时刷新前端监控/门户；上下文装配每次实时路由而非缓存。
