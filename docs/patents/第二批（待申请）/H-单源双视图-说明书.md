**申请人**：[需核实：北京青羽智行科技有限公司]

## 技术领域

本发明涉及人工智能与数据管理领域，尤其涉及一种在同一结构化数据底座上派生"时间线叙事（故事线）"与"关系图谱（网络）"双视图的构建方法、系统及计算机程序产品，用于解决 CRM 数据在"故事视图"与"图谱视图"之间重复存储、口径分裂、无法对账的技术问题。

## 背景技术

在客户关系管理（CRM）与 AI 原生智能体平台中，同一业务数据常需以两种形态被消费：**叙事形态**（按时间顺序讲述"发生了什么故事"——客户跟进、商机推进、决策历程）与**关系形态**（按实体连接展示"谁和谁什么关系"——组织图谱、责任链、影响路径）。现有技术通常分裂建设：

1. **双表/双系统重复存储**：为支持时间线单独建一张"事件流水表"，为支持图谱单独建一套"关系系统"，同一事实在两处各存一份，写入时需双写、对账时口径分裂，数据不一致率高（行业调研显示大量企业 CRM 数据不准确）。
2. **图谱=图谱、故事=故事的割裂**：只做图谱的系统（如 Attio 类）看不到事件演化，只做记忆流的系统（如 Lightfield 类）看不到关系结构——两者无法在同一底座上融合消费。
3. **时间基准漂移**：时间线按创建时间排序、决策列表按决策时间排序、图谱按更新时间标记——同一事件在不同视图间排序口径不一致，叙事失真。
4. **双视图不可审计**：时间线条目与图谱节点无法回链到产生它们的决策记录，追溯中断。

## 发明内容

本发明提供一种基于单一结构化存储派生双视图的构建方法，通过"单源存储 + 只读聚合派生 + 统一时间基准 + 受控边图谱寻址 + 双视图上下文融合 + 决策回链审计"的技术手段，实现同一数据一次治理、双模复用，杜绝重复存储与口径分裂。

### 技术方案概览

- **单一底座**：粒子表 + 关系边表 + 记忆日志表 + 决策记录表，同源存储不重复；
- **视图 1·时间线叙事**：四源只读聚合（events/tasks/decision/memory_log），不落库、不复制，统一时间基准排序；
- **视图 2·关系图谱**：同底座受控边 + 图分析（度数中心度/影响传播），不另建存储；
- **融合注入**：时间线正序叙事供推理，图谱关系寻址供多跳关联，上下文层按场景融合；
- **审计回链**：双视图元素均携决策标识，可回链决策记录，形成可追溯链。

### 有益效果

- 单源双视图：同一数据一次治理、双模复用，杜绝重复存储与口径分裂；
- 只读聚合：时间线不落库，视图派生无状态、可随时重建；
- 统一时间基准：COALESCE(decided_at, created_at) 单一声明，杜绝跨视图排序漂移；
- 图=寻址、故事=推理：双视图分工明确，融合注入提升决策上下文质量；
- 决策回链：双视图任意元素可追溯至生成它的决策记录，满足审计要求。

## 具体实施方式

**实施例 1（单一底座，对应权利要求 1 的 S1）**

结构化存储底座包含：粒子表（`src/particles/particleRepo.js`，含 tenant_id 复合主键隔离）、关系边表（受控边七类 E1–E7，`src/decision/edgeDimensionSpec.js:18-38`）、记忆日志表（`crm.memory_log`）与决策记录表（`crm.decision`，33 列含 decision_id）。四类数据各自单份存储，不按视图重复。

**实施例 2（时间线叙事视图派生生，对应权利要求 1 的 S2 与权利要求 2–3）**

`src/context/timelineSource.js` 实现：时间线是**派生视图而非存储资产**——事件、任务、决策、记忆日志四源**只读聚合**（`buildTimelineRows`），不落库；时间基准统一为 `DECISION_TIME_BASIS = COALESCE(decided_at, created_at)`（决策时间优先、创建时间兜底），杜绝跨视图基准漂移；同秒同实体同类型去重；倒序输出给前端、正序输出给叙事注入（`chronological`）。

**实施例 3（关系图谱视图派生生，对应权利要求 1 的 S3 与权利要求 4）**

同一底座派生图谱：受控关系边（七类边维度）为寻址路径，图分析（`src/decision/graphAnalytics.js`）计算度数中心度与下游影响传播，识别关键节点与影响路径；图谱不另建存储，直接查询同源粒子与边。

**实施例 4（双视图融合注入，对应权利要求 1 的 S4 与权利要求 5）**

上下文装配（`assembleContextV2`/`assembler`）将时间线（故事线）与图谱（关系网）在上下文层融合注入智能体：故事线按正序叙事供 LLM 推理（还原因果顺序），图谱按关系寻址供多跳关联查询（还原责任链/影响路径）；两视图共享同一事实源，融合结果仍可回溯。

**实施例 5（决策回链审计，对应权利要求 1 的 S5）**

时间线条目与图谱节点均可回链到决策记录（decision_id），形成"决策→视图→决策"可追溯链；审计四问（Q1–Q4）与决策数据同源（`auditability.js`），满足"谁决策、依据什么、是否越权、如何改"的完整审计要求。

**实施例 6（与写时构建的衔接，对应权利要求 6）**

与 G 件（写库即构建）互补：粒子与边的写时物化钩子（G 件）保证数据落库即建图；本件（H 件）保证双视图从同一即时物化底座派生——"写时构建底座 → 双视图派生 → 上下文融合 → 决策回链"形成完整数据底座专利族。
