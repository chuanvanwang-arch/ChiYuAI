## 一、为什么简化：专利视角的披露红线

平台已梳理 A/B/F/G/H/ARCH 六件专利草案，判断新颖性的口径是「**概念已公开、结构未公开 → 安全**」。
对外材料一旦写出**结构层**内容（内部字段、判定规则、分档阈值、维度清单、根因 taxonomy、闸层顺序），
即构成**自我披露**：既可能成为自己专利的现有技术，也给规避设计提供图纸。

因此 v4 执行一条硬规则：

> **PPT 只讲「能做什么 + 给客户带来什么」，不讲「内部怎么判定」。**
> 机制一句话带过（能力层），实现细节一律不下沉（结构层）。

v4 已加兜底声明（P14 页脚）：*「平台核心机制已申请发明专利，实现细节可在保密前提下另行深度交流。」*

## 五、后续披露管控建议

1. **统一对外口径**：公众号、路演 pitch、客户 PPT、投标文件共用同一套「能力层」话术，结构层一律不外发。
2. **申请日前禁新披露**：A/B/F/G/H/ARCH 提交前，不再发表「写库即构建 / 双模同源 / 九尺子 / 八闸」类文章。
3. **需要细节的场景走 NDA**：客户技术交流讲机制时，先签保密协议，再提供内部结构说明。
4. **新素材先过自查**：任何对外稿件发布前，跑一遍敏感词清单（字段名 / 判定规则 / 阈值 / 闸序 / 根因 taxonomy）。
