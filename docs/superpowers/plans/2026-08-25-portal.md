## T1 · schema.js 协议常量 + 值域 + Action 白名单
**文件**：`src/page/schema.js`（新建）
**职责**：导出
- `PAGE_TYPES = ['dashboard','table','form','detail','intake','workspace']`
- `COMPONENT_KINDS = ['metric-card','table','goal-form','result-card','reasoning-trace']`
- `THEMES = ['light','dark']`
- `FILTER_OPS = ['eq','lt','lte','gt','gte','contains']`
- `AGG_FUNCS = ['count','sum','avg','latest']`
- `PARTICLE_TYPES_ENUM = ['CRM_DEAL','CRM_ACCOUNT','CRM_CONTACT','CRM_PRODUCT','CRM_PRICE_LIST','CRM_PERSON','CRM_ORGANIZATION','CRM_KNOWLEDGE','CRM_UNSTRUCTURED_ASSET']`（对齐 particleModel.js 9 真粒子）
- `ACTION_WHITELIST = { read:['data-particle-read','crm-account-360'], write:['crm-deal-advance','data-particle-create','data-particle-update'] }`（对齐子系统三 whitelist）
- `CANONICAL_NAV = ['/dashboard','/deals','/accounts','/contacts','/products','/pricelists','/persons','/organizations','/knowledge','/workspace']`
- 状态字段集合 `STATE_FIELDS_PER_TYPE`（CRM_DEAL.stage 等，供 validator 做「状态仅 eq 不聚合」）
- 存量快照字段集合 `SNAPSHOT_FIELDS_PER_TYPE`（如 qty/amount，供 validator 做「仅 latest」）
**测试**（`test/page.test.js` T1）：常量存在且值正确；PARTICLE_TYPES_ENUM 含 9 项且不含旧值 `DEAL`/`ACCOUNT`；ACTION_WHITELIST.write 对齐子系统三（crm-deal-advance/create/update）。
**commit**：`feat(portal-T1): schema.js 协议常量+粒子值域+Action白名单`

## T2 · nlParser.js 解析映射（确定性规则）
**文件**：`src/page/nlParser.js`（新建）
**职责**：`parseNlToSchema(nl)` → `{schema, confidence, needsClarification, notes}`，**绝不产出 HTML**。
- 意图→type：看板/概览/分布→dashboard；表格/列表/明细→table；表单/录入→form；详情→detail；目标/工作台/任务→workspace；缺省 dashboard。
- 实体→粒子表：商机/交易/机会→CRM_DEAL；客户→CRM_ACCOUNT；联系人→CRM_CONTACT；人→CRM_PERSON；产品→CRM_PRODUCT；价格→CRM_PRICE_LIST；组织→CRM_ORGANIZATION；知识→CRM_KNOWLEDGE；资料→CRM_UNSTRUCTURED_ASSET。
- 指标→聚合：金额/总量→sum；数量/个数→count；比率/率→avg；最新→latest。
- 阈值高亮：「低于 X%/小于 X」→ highlight {when:{field:'xxx',op:'lt',value:X/100},color:'red'}；「超过」→gt。
- 动作→按钮：审批/推进→crm-deal-advance（仅当实体商机）；查看详情→crm-account-360（仅当实体客户）。
- 置信度：完整实体+指标+动作→0.9；有实体缺指标→0.7；缺实体→0.3+needsClarification；注入尝试（`<script>` 等）→0 + needsClarification + safe:false。
- notes 记录实体未识别/歧义（如「联系人」vs「人」）。
**测试**（T2）：看板意图→dashboard；商机→CRM_DEAL；缺实体→0.3+needsClarification；金额→sum；「低于 90%」→highlight red lt 0.9；注入→safe:false。
**commit**：`feat(portal-T2): nlParser.js NL→Schema 确定性解析`

## T3 · validator.js 4 粒子校验 + navigation 强制
**文件**：`src/page/validator.js`（新建）
**职责**：`validatePageSchema(schema)` → `{ok, errors[]}`。校验：
1. type ∈ PAGE_TYPES；title 非空字符串；layout 合法（columns 1-4、theme ∈ THEMES）。
2. 每个 component：kind ∈ COMPONENT_KINDS；dataBinding.particleType ∈ PARTICLE_TYPES_ENUM（**旧值如 DEAL/ACCOUNT 直接拒绝**，非静默映射）。
3. **状态字段约束**：filter.field ∈ STATE_FIELDS_PER_TYPE[type] 时 op 必须 eq；metrics 聚合状态字段→拒绝（枚举不可聚合）。
4. **存量快照约束**：metrics.field ∈ SNAPSHOT_FIELDS_PER_TYPE[type] 时 agg 必须 latest。
5. **Action 白名单**：actions[].action ∈ ACTION_WHITELIST.read ∪ write；未知→拒。
6. **navigation 强制**：navigation.to ∈ CANONICAL_NAV，否则拒。
**测试**（T3）：未知粒子 CRM 旧值→拒；stage 聚合→拒；stage filter op=gt→拒；snapshot field agg=sum→拒；未知 action→拒；navigation.to 非法→拒；合法 dashboard→ok。
**commit**：`feat(portal-T3): validator.js 4粒子护栏+navigation强制`

## T4 · guardrails.js 输入层护栏
**文件**：`src/page/guardrails.js`（新建）
**职责**：`guardNlInput(nl)` → `{safe, reason}`。拦截（正则，大小写不敏感）：`<script`、`javascript:`、`on\w+=`（onerror/onclick/onload 等）、`eval(`、`<iframe`、`<img on`；命中任一项→safe:false + reason（注明命中模式）。npm 无依赖纯函数。
**测试**（T4）：`<script>`→safe:false；`javascript:alert(1)`→false；`onerror=`→false；`eval(`→false；正常「给我一个看板展示商机金额」→safe:true。
**commit**：`feat(portal-T4): guardrails.js 输入层护栏(拦截注入)`

## T5 · renderer.js 唯一渲染出口
**文件**：`src/page/renderer.js`（新建）
**职责**：`renderPage(schema, data)` → `{html, warnings[]}`。
- 渲染前先 `validatePageSchema`，非法→`{html:'', warnings:['schema_invalid']}`。
- 四态：数据为空→empty 态；data 为 loading→loading 态（骨架）；data 为 error→error 态+原因；部分字段缺失→partial 徽标。
- **动态值转义**：所有插值过 `escapeHtml`（`& < > " '`）。
- **交互仅 data-action 声明式**：按钮/链接输出 `data-action="crm-deal-advance"` 等属性，**无 onclick/inline JS**。
- **强无 `<script>`**：输出后检测含 `<script`→剔除该段并 warning。
- 布局：columns 用 CSS grid（inline style 或 `<div style="grid-template-columns: repeat(n,1fr)">`）；theme light/dark 用 class。
- 组件渲染：metric-card（标题+数值+highlight 色）、table（thead+tbody）、goal-form（输入框+data-action 提交）、result-card、reasoning-trace（占位列表）。
**测试**（T5）：合法 schema→html 含组件标记；动态值 `<b>`→`&lt;b&gt;`；无 `<script>`；data-action 出现；highlight red 出现；非法 schema→warnings；empty/loading/error 态文案。
**commit**：`feat(portal-T5): renderer.js 唯一渲染出口(转义/data-action/无script/四态)`

## T6 · pageStore.js 页面生命周期 + routes 接线
**文件**：`src/page/pageStore.js`（新建）+ `src/http/routes.js`（扩展）
**职责**：
- `createPageFromNl(nl)`：guardNlInput→parseNlToSchema→validatePageSchema→存 draft（内存 Map，page_id=uuid）→返回 `{page_id, schema, confidence, previewHtml}`。生成记录保留 `{nl原文, schema, confidence, notes}`。
- `listPages()`：draft/published 清单。
- `publishPage(page_id)`：draft→published（**显式发布，不自动覆盖人工页**）。
- `revertPage(page_id)`：published→draft。
- `getPageHtml(page_id)`：renderPage（注入内存数据或空数据）。
- routes.js 新增：`POST /api/page/from-nl`（body:{nl} → store.createPageFromNl）；`POST /api/page/:id/publish`；`GET /api/pages`（list）；`GET /api/page/:id/preview`（返回 previewHtml）。
**测试**（T6）：createPageFromNl 合法 NL→draft 存续+previewHtml 有值；注入 NL→safe:false 不落库；publish→published；revert→draft；list 含该页；重复 publish 不覆盖人工页语义（已 published 再 publish 幂等）。
**commit**：`feat(portal-T6): pageStore 生命周期 + routes 接线`
