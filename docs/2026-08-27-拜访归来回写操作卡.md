## §1 现场 6 问（拜访中快速记，回来填脚本）

| # | 问题 | 记什么 |

| 1 | 做什么 | 产品类型（礼盒/彩盒/画册/不干胶/说明书…） |

## §2 填脚本 §A 输入（3 分钟）

打开 `tmp/visit-return-writeback.mjs`，填 §A 的 **8 行**：

| 行 | 含义 | 填法 |
|---|---|---|
| `company` | 公司名 | 拜访谈到完整名就填；没谈到先填占位名（如"XX 行业客户（XX 介绍）"），回来确认后补 |
| `contact` | 联系人 | 姓名/称呼 + 电话（可空） |
| `industry` | 行业 | 可空，谈到了才填 |
| `focus` | 相关印刷品 | 礼盒/彩盒/画册/不干胶/说明书… |
| `pain` | 客户痛点 | 如"旧供应商色差不准"——这是切入机会 |
| `needs` | 需求六要素 | product/qty/spec/timeline/budget/decision_chain 按现场 6 问填 |
| `next` | 下一步 | **必填**（报价/寄样/约下次/待确认 + 时限）；没有下一步=白跑 |
| `has_deal` | 有没有明确需求 | `true`=建商机（走 OPP_QUALIFY 机会评估闸）；`false`=纯预热只建客户档案（LEAD_FOLLOW_UP 闸） |

再设两个开关：

| 开关 | 值 |
|---|---|
| `COMP_KNOWN` | 老客户拜访=`true`（先填 `ACCOUNT_ID`）；新客户=`false`（自动查重防重复建档） |
| `DEAL_ID` | 老客户已有商机→填商机 ID 走更新；空=新建商机 |

## §3 跑脚本（1 分钟）

```bash
cd D:/system/CRM-ai-native
C:/Users/wangchuan08/.workbuddy/binaries/node/versions/22.22.2/node.exe tmp/visit-return-writeback.mjs
```

脚本自动完成（全部走决策第 0 闸，无决策不写）：

1. **查重**：新客户时先查同名客户——命中则阻止重复建档，提示填 `ACCOUNT_ID` 走更新；
2. **决策**：按 `has_deal` 自动选闸（`OPP_QUALIFY` 有明确需求 / `LEAD_FOLLOW_UP` 纯预热），`decider=wang-chuan`；
3. **客户**：新客户建档（含 visit_note 首次记录）/ 老客户更新（追加 visit_notes、合并 pain_points）；
4. **商机**：有需求则建商机（opportunity 阶段，有预算概率 0.4 / 无预算 0.25）+ `belongs_to` 边（商机→客户）；
5. 输出 `DONE {decisionId, accountId, dealId, edgeId, next}` → 把这 4 个 ID 记到今天的工作日志。

## §4 查重/异常处理

| 输出 | 含义 | 处理 |
|---|---|---|
| `⚠️ 查重命中` | 同名客户已存在 | 不要新建！填 `COMP_KNOWN=true` + `ACCOUNT_ID` 走更新 |
| `DECISION ...` | 决策落库成功 | 记 decisionId |
| `ACCOUNT_UPDATED` | 老客户档案已更新 | 确认 visit_notes 追加成功 |
| `DEAL_UPDATED` | 老商机已追加拜访记录 | 确认 spec/next 更新正确 |
